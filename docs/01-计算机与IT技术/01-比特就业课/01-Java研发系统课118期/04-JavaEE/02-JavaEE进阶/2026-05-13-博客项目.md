## JWT 
[JWT](https://www.jwt.io/) 全称叫作 `JSON Web Token` 用来解决微服务项目中，`Session` 不能共享的问题。


### 执行流程
JWT 的过程是这样：

||
1. 客户端发起请求，**服务端会经行统一拦截处理**，如果需要令牌，那么就会校验令牌，如果校验不通过，那么就会返回错误信息。
2. **客户端收到令牌过期/错误的信息后，会给用户跳到用户登录的页面**。
3. 在用户输入正确的信息，执行登录后，**获取到服务器生成对应的令牌返回给客户端**
4. **客户端收到令牌后，把它存储在本地上，之后访问服务端都会携带这个令牌**
5. 服务器接收到了请求，依然会校验令牌的合理性，如果正确，那么就会放行，让客户端收到正确的响应
||

### 组成部分
它分为**头部，载荷和签名**
- `头部`：用来存储**加密算法**
- `载荷`：存储令牌的相关信息，**这个是没有加密的**
- `签名`：用来校验令牌是否正确，这个是**防篡改**（类似网络原理中的校验和）

> `JWT` 配合 `Redis` 是可以设置为没有状态的，因此任何人只要拿到对方的 `JWT`，那么就会以对方的身份经行访问。
> 如果服务端安全性偏低，就可能会出现安全问题
> 
> 当然，一般情况下，**只要不乱下载软件，访问公共电脑后及时退出**，一般是拿不到对方的 `JWT` 的
