# 90-问题与收获
## 问题
### `buildActivityPrizeDetail` 这个方法为什么不使用 `BeanUtils`
这里面的方法是多个对象合并为一个对象，因此需要使用 `set` 而不是使用 `BeanUtil`, `BeanUtil` 一般是适合于单个对象的拷贝。如果使用 BeanUtils, 那么可能会以下几个问题：
1. 名称需要约定一样
2. **枚举类型需要转换**
3. **派生属性还需要专门处理**
   > 派生属性是想 valid 这样的属性，在实体类里面是没有的，但是如果不设置那么前端处理会比较麻烦
### 数据库中直接存储枚举的值合适吗？

这个是要根据具体的业务场景来看的：
1. 它是不是涉及到了**频繁的修改**？
2. 存储的**数据量**大约在多少数量级
3. 有哪些地方是要调用这个枚举的，只有**一个地方还是有多个地方**？

然后根据这些业务，来设置相关的表结构。

### 抽奖使用了 RabbitMQ, 那么幂等性是如何保证的呢？
这个幂等性是不单单考一个步骤来保证的，它是靠多个模块共同保证的
1. 在首次发送消息的时候，**先把相关的记录通过 `DrawRequestDO` 这个对象记录在 `MySQL` 中**
2. **通过 `markProcessing` 抢占，把活动的状态设置为“执行中（`PROCESSING`）”**，这样后续的重试（比如 `RabbitMQ` 异常重试）可以让它通过
3. 通过 `selectByIdForUpdate` **串行化执行更新语句**，以免更新错乱
4. 最后通过把 **“活动ID-奖品ID”** 这样的唯一键组合，保证数据结果唯一性

## 收获
### Jackson中的tryParse
`Jackson` 中的 `tryParse` 方法是一个不错的统一处理的思路
1. 先**定义一个函数式接口 `Callable`**，里面只有一个 `call` 方法
2. 然后用**一个函数 `tryParse` 封装一下**，里面用 `Callable` 和 `Exception`
3. **函数里面进行统一处理**：使用 `try-catch`
4. 其他要实现的功能只需要调用 `tryParse`，然后**只需要写逻辑就可以了，就不需要统一异常处理了**
